Distributed E-Commerce Microservices

A distributed e-commerce backend where independent services (store, bank, delivery, email) coordinate a single order reliably over messaging, staying consistent even when individual services fail.

Features

  • Place an order that reliably coordinates payment, delivery, and notifications behind the scenes.
  • Never double-charged, never oversold, even if a service fails mid-order.

Why I built it

I wanted to implement the resilience patterns real distributed systems rely on, not just read about them, by building an order flow that stays correct when parts of it fail.

Core technical

  • Decoupled four services over RabbitMQ so one slow service can't block the rest.
  • Guaranteed zero message loss through outages with the transactional outbox pattern.
  • Prevented customers being double-charged by making every handler idempotent.
  • Kept orders consistent with the Saga pattern (auto-rollback of stock and payment) and stopped overselling with row-level locks.
